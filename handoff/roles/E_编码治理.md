# E 接棒：编码治理 D3

## 读取和前提

读取 C 的正式需求、D 的 blueprint/ADR/权限模型/接口、不变量与 B 的验证约束。以已评审架构确定权限，不能通过写一张“禁止”表就宣称权限已执行。

## 让 AI 做什么

1. 创建根目录 `AGENTS.md`：构建目标、阅读顺序、基线、可读/可改/冻结区域、模块组织、集成契约、验证要求。
2. 创建 `docs/code-governance/structural-constraints.md`、`mcp-tool-manifest.md`；课程结构中的工具清单位于该目录，不另建一个含义不同的根文件。
3. 形成 `.opencode/permissions.jsonc`、`.opencode/rules.md`、`.agent/rules.md`，默认拒绝、明确白名单，反馈组件无成绩库写权限，冻结计算器改动需要 ADR 和真人批准。权限配置语法应根据实际使用的 OpenCode 版本核验。
4. `.opencode/rules.md` 是课程中的 human-only 文件：AI 可以在其他草案文件提出内容；由真人审阅并完成该受保护文件，不让 AI 给自己授予权限或假签。
5. 与 D/A/B 商定真正的运行时隔离、认证审批依赖和执行机制。API/permissions snapshot 是 B 的集成证据，需要绑定实际实现/配置；应用尚未存在时留待 A/B 补齐，不能填写假哈希。

## 交出

交 A：完整阅读顺序、已批准接口、权限配置及机制说明、冻结列表、构建/验证规则、真实人工审阅证据。A 需按这些约束创建 Prompt 并先出执行计划。若某个工具/规则必须真人维护，在交接中指出具体文件和待办，不借缺口绕过边界。使用交接模板记录，并更新状态。
