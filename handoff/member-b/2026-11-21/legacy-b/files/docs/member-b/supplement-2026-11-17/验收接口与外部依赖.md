# B 验收接口与外部依赖说明

本文件与可执行测试一起提供评审对象，不代替 A 的设计确认或具体实现计划批准。A 的源码在本轮没有修改。

## 已有 API 保留

`src.score_calculator.calculate_score(rubric_object, scores)`；
`src.feedback_engine.evaluate(essay, rubric, prompt, settings, transport=..., mode=...)`；
`src.feedback_engine.validate_feedback(raw, essay, rubric)`；
`src.grade_store.GradeStore.create/get/approve`。

评分使用 D 已选择的精确 Fraction 累积和一次 HALF_UP；无需改成旧 B 的扁平模块或引入第二个 calculator。

## B 测试所依据的架构义务

- ADR-0001：每 criterion 有数字 confidence；缺失、无效、低于0.80升级，0.80包含；区分 invalid_confidence/low_confidence。模型 final_score 忽略；其余未知字段仍拒绝。
- ADR-0002：信任根来自可信配置，签名绑定提交/提案/rubric版本/确认分数；拒绝未知 signer、坏签名、分数替换和跨提交重放。名字只是 audit label。失败无 grade/状态变化，成功仍由 calculator 计算并原子持久化。
- ADR-0003：稳定 submission_id、同内容幂等、异内容冲突、显式 schema v2/迁移；配置读取移到 CLI，feedback_engine 不导入 os。

## 可执行测试使用的 additive seam（待 A/D 确认）

```python
GradeStore(path, trusted_keys={key_id: raw_ed25519_public_key_bytes})
store.create(essay, rubric, advice, submission_id="stable-id")
store.approve(proposal_id, proposal_hash, confirmed_scores, reviewer_label,
              approval={"key_id": key_id, "binding": {...}, "signature": hex_signature})
```

binding 字段为 `submission_id/proposal_hash/rubric_id/rubric_version/confirmed_scores_sha256`；测试用现有 canonical JSON 的 UTF-8 bytes 签名，签名十六进制编码，验证公钥为原始字节。签名方案、域隔离、真实 key 托管、撤销与轮换需 A/D/E 评审。若采用不同但满足同等义务的 API，先调整测试-only 合同，再实施；不能要求 agent 编造 verifier。

测试的 audit 目标字段还包括 `verified_key_id`、`approval_binding`、`approval_signature` 与 `confirmed_scores_sha256`；`reviewer` 仍只是可读标签。有效签名正面对照也覆盖升级案例在完整人工分数和理由下被解决的路径。字段命名同样待 A/D 确认，不能仅为通过测试增加没有验证行为的假字段。

当前 8 项 signing 测试在 `trusted_keys` 参数缺失处给出明确失败，而不是导入失败。提供新 API 后将继续执行签名、替换、重放、审计篡改和正面对照的业务断言。它们不能在缺实现时跳过，也不能声称已经验证了真实教师身份。
