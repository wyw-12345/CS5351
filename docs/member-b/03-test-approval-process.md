# Tests before implementation — real approval workflow

1. C/D/E deliver an approved requirement/architecture/permission baseline. Add real independent teammate GitHub usernames to `docs/verification/policy.json` in a human-reviewed governance PR. The initial empty list deliberately blocks approvals.
2. Create a **tests-only PR** containing new/updated `test/` cases and `docs/verification/test-map.yaml`, plus relevant requirement/contract documents. No `src/`, `tools/`, runtime prompt/model or dependency change. Include a reviewed `docs/verification/test-plans/<feature>.json` scope plan (copy `test-plan.example.json` in this directory). List precise REQ IDs, exact implementation paths, changed test paths, and the exact `file::Class.method` locators per requirement in `test_locators`. Each chosen locator must appear in the reviewed and current test maps; other existing locators can stay unchanged.
3. Independent human reviewer reads tests and execution plan, checks that adversarial tests fail without enforcement, records approval on the exact PR head, and merges into **`test-baselines` before implementation starts**. Protect this branch with human review, stale-approval dismissal and no direct/force pushes; it intentionally does not require application tests to pass. The implementation branch starts from this approved test baseline. Main requires all six CI checks and receives tests plus implementation only when green. CI verifies that the approved merge is an ancestor of the first implementation commit, not merely an ancestor of the final HEAD.
4. Implementation PR adds an entry to `docs/verification/implementation-approvals.json`: `{test_pr: 123, plan_path: "docs/verification/test-plans/calculator.json", implementation_paths: ["src/score_calculator.py"], requirement_ids: ["REQ-INV-001"]}`. Paths are exact, not globs. Link the earlier tests PR. The tests in the implementation branch must be byte-identical to the tests present before its first implementation commit. Every test path changed versus main must also match a verified tests-only merge. The gate checks the reviewed plan and map, exact locators, GitHub review, merge ancestry and timestamps. Fetch the tests baseline history before implementing; CI checkout must retain full history.
5. Human reviewer verifies the full raw session and actual approval-before-code ordering. Git timestamps alone cannot prove when work began. A changed test requires a new tests-only approval cycle; it must not be patched within the implementation PR to excuse a failure.
6. Safety PR additionally updates ADR, API and permission snapshots and obtains human review of the current head. After a review event, rerun the existing failed workflow from Actions to fetch the new API evidence; a review alone does not rerun `pull_request` workflows.

Bootstrap caveat: this B package has no approved team baseline or human review. Its initial local commits are preparation evidence, not retroactive test approval. Do not claim the initial tool implementation met gate 1. Activate enforcement only after the human-reviewed baseline and real review allowlist exist; retain the bootstrap deviation in the report.
